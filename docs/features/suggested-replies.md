# Suggested replies

When an answer asks the user for a decision, codx-junior can offer the likely
answers as **buttons** instead of making the user type them. The buttons are
generated by the model itself, shown at the bottom of its answer, and the user
can always ignore them and write a different reply.

## How it works

1. The chat system prompt explains the `options` protocol to the model
   (`RESPONSE_OPTIONS_SYSTEM_PROMPT` in `chat_prompt_builder.py`).
2. When a closed set of answers makes sense, the model ends its response with a
   fenced block tagged `options` containing a JSON array.
3. The client strips that block from the rendered markdown and renders one
   button per entry (`ChatResponseOptions.vue`).
4. Clicking a button sends its `value` as the next user message. If the user is
   already typing, has attachments, or is editing a message, the value is
   placed in the composer instead so nothing is lost.

The raw block is kept in the stored message content, so the conversation history
is unchanged and the buttons survive a reload. Block editing re-attaches the
block automatically (`withResponseOptions`).

## Protocol

````markdown
Should I apply the migration?

```options
[
  {
    "label": "Yes, apply it",
    "value": "Yes, apply the changes",
    "description": "Run the migration now",
    "style": "primary"
  },
  { "label": "No", "value": "No, leave it as is", "style": "danger" }
]
```
````

| Field | Required | Description |
| --- | --- | --- |
| `label` | yes | Button text. Keep it short (about 6 words). |
| `value` | no | Exact user message sent on click. Defaults to `label`. |
| `description` | no | One short line shown under the label. |
| `style` | no | `primary`, `secondary`, `accent`, `danger`, `warning`, `success`, `info` or `ghost`. `error` is accepted as an alias of `danger`. |
| `icon` | no | Font Awesome class, for example `fa-solid fa-database`. |

A plain bullet list is also accepted as a compact fallback:

````markdown
```options
- Yes
- No
- Explain the trade-offs first
```
````

Use `label => value` when the visible label and the sent message must differ.
The fence languages `options`, `suggestions`, `suggested-replies`,
`quick-replies`, `choices` and `replies` are equivalent.

## UI behaviour

- Only the latest assistant message shows its suggested replies. Once the user
  replies (by clicking or typing), the buttons disappear with that message.
  Harness mode is the exception: its transcript is a durable review surface, so
  the replies of every assistant turn stay clickable.
- Buttons are disabled while the answer is streaming and in read-only chats.
- The composer stays available the whole time: the user can write any other
  answer or edit the one a button inserted.
- A suggested reply is treated as a normal user message: it is persisted,
  counted in the budget and sent to the model like typed text.
- Up to 12 options are rendered; empty and duplicated entries are dropped and
  over-long labels/descriptions are truncated by the parser.
- An unterminated block is hidden while the answer streams. A malformed block
  is left visible instead of silently removing part of the answer.
- In a voice call the option labels are announced at the end of the answer
  (`Options: …`); the JSON block is never read aloud as code.
