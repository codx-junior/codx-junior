# codx-junior 0.0.1

**The AI developer you host.** Your repo. Your model. Your machine.

0.0.1 is the first public release: one container, one model, one repository, and
a project-aware agent that reads the code, makes the change, runs the tests and
shows you the diff before you commit.

It is deliberately small. The company OS, autonomous agents, meetings, browser
desktops and the human multi-user team are hidden for this release; the AI agent
team ships now. The product you install is the sharp edge of the platform: **a
real change, reviewed, on your machine.**

::: tip The one loop 0.0.1 has to nail
`install → connect model → add repository → chat → agent edits and tests → review the diff → commit`
:::

## Why 0.0.1 is different

### 1. You own the whole loop

One Docker container on your server, one OpenAI-compatible model, one project
folder. Code, prompts, keys and the knowledge index stay on your machine. No seat
subscription and no vendor model lock-in.

### 2. A team, not a single assistant

PM, developer, QA and security profiles each carry their own instructions,
tools and model. A task picks the role; the shared board carries the handoff;
you review the diff. A fullstack change is a vertical slice worked by a team,
not one mega-prompt.

| Profile | What it owns | What it hands back |
| --- | --- | --- |
| **project / PM** | Scope, acceptance criteria and the task breakdown. | A board card the team can work. |
| **software_developer** | The implementation across backend and frontend. | A diff and the tests that prove it. |
| **qa / qa_automation** | The verification plan and the regression suite. | A test run and a list of what still fails. |
| **ciso** | Secrets, dependencies and the security gate. | Findings and a pass/block verdict. |
| **analyst** | Requirements and architecture context. | A sharper task, less rework. |
| **human (you)** | Direction, trade-offs and the merge. | The final commit. |

Fifteen profiles ship by default. The **human** multi-user team (invitations,
shared channels, messenger) is 0.1; the AI team works today.

![The shared team board with role chips](/images/0.0.1/team-board.png)

*The shared board: each task carries its role, status, priority and project.*

### 3. The project is the context, not the open file

Every chat is bound to a repository and a knowledge index built from it.
Profiles carry your standards, stack and review rules into every turn, so you
stop pasting files and re-explaining your architecture.

### 4. The agent shows its work

Tool calls, file edits, test runs and diffs are visible in the workspace. The
agent proposes; you review the diff and make the commit. There is no black-box
pull request to trust.

### 5. One workspace, not another editor tab

Chat, tasks, file explorer, knowledge search and Git review live in the same
browser workspace, with the repository as the unit of work. Keep your editor for
editing; use codx-junior for the change.

### 6. Open source, inspectable, extensible

AGPL-3.0, Python/FastAPI + Vue, a real REST API and a local-first knowledge store.
Self-host it for free, read every line, and bring the model you already pay for.

specialists instead of living in one long prompt.

## What changes in your day

* **A bug fix starts with a sentence, not a search.** Describe the outcome; the
  agent reads the repository, finds the files, patches them and runs the tests.
* **The work is handed off, not re-prompted.** A vertical slice gets a PM task,
  a developer profile for the API and UI, a QA pass and a security check. The
  board keeps the state; each role keeps its own instructions and model.
* **Your standards travel with the task.** Profiles encode the stack, the test
  command and the review rules once; every chat starts from them.
* **The diff is the handoff.** Tool calls, changed files and test output are on
  screen before the commit. No "trust me" step.
* **The bill is your provider's bill.** The container talks to the model
  endpoint you configured; no seat tax or reseller margin.

**Who should not use 0.0.1:** teams that need roles and shared channels, anyone
who wants an autonomous agent opening pull requests without review, and hosts
without Docker. Those are the 0.1+ features, not a missing checkbox.

## What ships in 0.0.1

**17 features**, grouped around the loop:

* **Get started** — installer, first run, admin access, projects, provider/model settings.
* **Build** — project chat, agent tool loop, the agent team (profiles), knowledge
  (RAG), file explorer, vibe coding.
* **Plan and ship** — tasks/Kanban, Git and code review.
* **Operate and extend** — global/project settings, REST + Socket.IO API,
  responsive shell, themes.

The full catalogue is in the [feature reference](/codx-junior.features). The
release decision, usefulness score and required fixes are in the
[0.0.1 feature matrix](https://github.com/codx-junior/codx-junior/blob/main/docs/product/v0.0.1-feature-matrix.md).

## What is *not* in 0.0.1

These features exist in the codebase but are hidden by the install-time feature
profile. They are the roadmap, not the promise:

* autonomous agents, autonomous tickets and the company ticket workbench;
* teams, messenger, meetings and the company assistant;
* dev containers, browser/desktop sessions, computer use and the infrastructure panel;
* the company business dashboard, CISO, budget, analytics and the in-app updater;
* MCP connections, plugins, voice, channel content and external actors;
* multi-user roles and invitations.

They remain in the tree behind the install-time feature list, so 0.1 can enable
them feature by feature without forking the product.

## Install in one command

**Requirements:** Linux with Docker 20.10+ and Compose v2, 4 GB RAM (8 GB
recommended), and one API key for an OpenAI-compatible provider.

```bash
curl -fsSL https://raw.githubusercontent.com/codx-junior/codx-junior/main/install.sh \
  | sudo bash -s -- --provider deepseek --key sk-xxxxxxxx
# -> http://<server>:19981
```

Then:

1. Sign in as `admin`, set a strong password and finish setup.
2. Add your repository: a Git URL or a folder path on the server.
3. Open **AI Models**, add your provider and pick the default model.
4. Open a chat and ask for a real change.
5. Review the diff, run the tests and commit.

Full instructions: [Install](/install).

::: warning First boot
Complete the admin password and setup **before exposing the port to the
internet**.
:::

## Try the demo loop

1. Add a small repository (or the bundled `demo-todo` example).
2. Ask: *“The remove command doesn't persist. Fix it and prove it.”*
3. Watch the agent read the code, patch it and run the tests.
4. Review the diff and commit.
5. Turn the next idea into a task on the board.

That is the whole 0.0.1 promise: **a real change, reviewed, on your machine.**

## The honest part

0.0.1 is early. It is tested for a **single developer on a single repository**,
with a model you provide. The known defects and the fixes that block the public
launch are in the feature matrix. Expect the API and the UI to change between
0.0.1 and 0.1.
