# TRAEFIK & ROUTING (READ THIS BEFORE DEBUGGING ANY URL)
codx-junior publishes almost every URL through Traefik: the SPA, the API
(`/api`), the auth middleware (`codx-junior-auth`), workspace apps, LocalAI, the
Traefik dashboard (`/traefik`) and every custom route. The routing table is
**generated by codx-junior** and polled by Traefik from
`GET /api/traefik/config` every 10 seconds.

Use the `traefik` tool first for anything that looks like a routing problem
("404", "502", "bad gateway", "the app is not reachable", "my route disappeared"):

| `traefik(action=…)` | Answers |
| --- | --- |
| `status` | Is the container running? Restarts? Effective command line, HTTP provider endpoint, static-config location and route statistics with open issues. |
| `routes` | The merged routing table (workspace / global / project) with rule, target, `managed_by`, enabled flag and per-route issues. Filter with `search`. |
| `config` (`source="file"`) | The static `traefik.yaml` (entrypoints, providers, ACME, access log settings); `source="generated"` returns the dynamic config Traefik actually polls. |
| `logs` | Container logs, **access logs included** (JSON), filterable with `search`; credentials in headers are masked automatically. |

Diagnostic order that resolves most incidents:

1. `traefik(action="status")` — a restart loop or a missing provider explains the symptom before any code reading.
2. `traefik(action="routes", search="<path or host>")` — if the route is missing or `enabled: no`, the problem is in the rule (config), not in the proxy.
3. `traefik(action="logs", search="<router or path>", tail=50)` — a `502` with `RouterName` set means Traefik matched the route but could not reach the backend; then use `docker_ps` / `docker_logs` on that backend.
4. `traefik(action="config", source="file")` — only when the provider itself is in question.

Rules of thumb:
* The HTTP provider endpoint **must** use the internal service name (`http://codx-junior-api:19980/api/traefik/config`); the public domain does not expose that port.
* Container routes are defined by Docker labels; codx-junior only *displays* them. Editing them means editing the container/compose labels, not the UI.
* HTTP-provider routes reference the auth middleware as `codx-junior-auth@docker` (override with `CODX_JUNIOR_TRAEFIK_AUTH_MIDDLEWARE`).
* `CODX_JUNIOR_TRAEFIK_CONTAINER` / `CODX_JUNIOR_TRAEFIK_CONFIG` point the tool at a different container name or static config path when the deployment differs from the installer.
